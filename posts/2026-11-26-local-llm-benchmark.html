Two GPUs, one model: local AI speeds on my home cluster

How fast my local AI models answer on my home server and gaming PC, and why a 20B model that fits on neither graphics card runs faster than a 12B model that fits on one.

  • Benchmark
  • Local AI
  • llama.cpp
  • GPU
Code ↗
Hardware
Server: Intel Core i5-2310 (4 threads), 16 GB RAM, NVIDIA GTX 1660 Super (6 GB), SSD. GPU PC: NVIDIA RTX 2080 Ti (11 GB). Wired 2.5 Gbit network between them.
Software
Ubuntu Server, llama.cpp build 12189 with RPC, llama-swap, running my Home AI Cluster setup
What was measured
Answer speed (tokens per second) for a 400-token answer, after the model had loaded
Date tested
November 2026

The question #

My home AI server has a 6 GB graphics card. My gaming PC has an 11 GB one. The model I most wanted to run, gpt-oss 20B, is an 11.3 GB file, so it fits on neither card by itself. llama.cpp can split one model across the GPUs of several PCs over the network, but every token then has to travel between the two machines. I wanted to know whether that is still fast enough to use every day.

How I measured #

Each model was asked to write about 300 words, with the answer capped at 400 tokens. I ran each request twice and kept the second result, so the time to load the model from disk isn't counted. llama.cpp reports the speed itself in its answer:

for i in 1 2; do
  curl -s http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' \
    -d '{"model":"gpt-oss-20b","messages":[{"role":"user","content":"Write about 300 words about rivers."}],"max_tokens":400}' \
    | jq '.timings.predicted_per_second'
done

For the 20B model I repeated the test three times, because the split over the network made it vary more than the others.

Results #

Answer speed after loading, in tokens per second (higher is faster). Server GPU = GTX 1660 Super, GPU PC = RTX 2080 Ti.
ModelSizeRuns onTokens/s
qwen3.5-4b2.7 GBServer GPU63
gemma-4-12b6.3 GBGPU PC42
gpt-oss-20b11.3 GBBoth GPUs, over the network57–71
team–3 models in turn~2.5 min per answer

Result

The 20B model, split across two PCs, wrote 57–71 tokens per second: faster than the 12B model running on a single, faster card. Pooling GPUs over a wired network is fast enough for everyday chat.

Why the bigger model is faster #

gpt-oss 20B is a mixture-of-experts model. It has about 21 billion parameters in total, but for each token it only uses around 3.6 billion of them. So once it is loaded, each token needs much less work than its size suggests, and less than a 12B model that uses all of its parameters every time. The network adds some delay to every token, which is why its speed moved between 57 and 71, but it still came out ahead.

For a sense of scale: a token is roughly three quarters of an English word, so even 42 tokens per second is about 30 words per second, several times faster than anyone reads.

team is a different case. Two models write an answer each, then a third reads both and writes the final one, one after another. That costs about two and a half minutes per answer, so I use it only when the answer matters more than the wait.

Limits of this test #

  • One machine of each kind, one prompt, and two or three runs per model. It shows what to expect on similar hardware, not exact numbers.
  • Only answer speed after loading was measured. Loading a model the first time takes longer: its file is read from disk and, for a split model, sent over the network to the other PC.
  • The network was wired 2.5 Gbit. Over Wi-Fi, splitting a model is much slower.
  • Hermes 4 14B, which I added later, hasn't been measured yet. I'll add it here when it has.

Try it on your own hardware #

The whole setup is open source as home-ai-cluster on GitHub↗. After installing it, run the command above on the server with your own model names to compare.
